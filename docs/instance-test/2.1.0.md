# 实例测试留档：2.1.0

> 2.1.0 发布前的实例测试。两个真实需求：库存管理系统（AI 客服 + 知识库）、制造企业接入 AI 知识库。
> 完整文档与源码归档在本地 Gitea `gewumind-instance-test`；本地副本 `/data1/test/inventory-ai/`、`/data1/test/2.1-实例测试/`。

## 需求

1. **库存管理系统（含 AI 客服）**：4 表 + 12 magic-api 端点 + 11 菜单 + 2 个 AI 只读工具 + 知识库 + 6 个 UI 组件。验收 A1–A10。
2. **制造企业接入 AI 知识库**：启用 → 导入 → 授权 → 问答（带引用）→ 验收，验证知识库在真实使用路径下可用、无 bug。

## 环境

- 源码：本地 Gitea `gitea/gewumind-boot` main @ `56fa8e0`（2.1 开发版，含 K08 确定性知识路由修复）
- 发行版：`dist/gewumind-boot-app-2.0.0/`（`build-dist.sh --skip-build` 组装，内核 sha256 `64271ed3…`）
- 数据库：`gewumind_inventory_test`（全新，MySQL 8.0.46）；端口 9210
- 初始化：`01-baseline` + `02-ai-2.0` + `04-ai-kb-2.1`

## 验收结果

- 库存系统 **A1–A10 全过**：新实例 + admin 登录（license 11/11）、商品/仓库/库存 CRUD、AI 数据问答（只读、只查本人、零幻觉）、知识库引用问答、越权 0 泄漏、语音弱网降级。
- 知识库接入：启用 → 导入 → 授权 → 问答带引用，全链路通过。

## 踩坑（已修复）

- `sys_configure` 的 `ai.*` 开关 `is_del` 须为 `0`（只改 `configure_value` 不生效，`is_del=1` 会让配置对 `is_del=0` 的读取不可见）。
- magic-api `bundle_apply` 的 `group` 字段被当作 path。
- magic-script 不支持 `new Date()` / `UUID.randomUUID()`。

详见 Gitea `gewumind-instance-test` 与 `/data1/test/inventory-ai/实例测试文档-库存管理系统.md`。
