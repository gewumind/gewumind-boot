# 实例测试留档：2.2.0

> 2.2.0 发布前的实例测试。真实需求：**电商订单咨询 H5 客服 + 转人工**。
> 完整工程归档在本地 Gitea `gewumind-instance-test`；本地副本 `/data1/test/h5-ecom-2.2/`。

## 需求

**电商订单咨询 H5 客服**：商城站点嵌入 H5 客服组件（`h5-widget.js` → iframe `/#/h5/chat?channel=<id>`）。
访客以**手机号绑定身份**，向 AI 咨询**本人订单**（订单号/商品/金额/状态/物流）；AI 通过只读工具
`order_query` 查本人数据（**零越权**：匿名无手机号→澄清/拒答，跨用户查他人→0 泄漏）；
访客可**转人工**（落 `sys_ai_handoff` 工单 + 管理端工单列表）。渠道支持品牌/欢迎语/免责声明/主题色定制。

## 环境

- 源码：本地 Gitea `gitea/gewumind-boot` main（2.2 开发版，含 H5 通道/转人工/管理端/品牌）
- 发行版：`dist/gewumind-boot-app-2.1.0/`（`build-dist.sh --skip-build` 组装，内核 0.4.1，含 2.2 H5 能力）
- 数据库：`gewumind_h5_ecom_test`（全新，MySQL 8.0）；端口 **9250**
- 初始化：`01-baseline` + `02-ai-2.0` + `04-ai-kb-2.1` + `05-ai-h5-2.2`
- 业务：3 表（`t_customer`/`t_product`/`t_order`）+ 种子（3 客户/4 商品/10 订单）
  + magic-api 端点 `/电商客服/ai/order`（只读按 `userId` 查本人订单）+ 管理端菜单
- License：dev license（`features:["*"]`，12/12 能力，含 `AI_H5`）；LLM `qwen3.8-27b`（OpenAI 兼容）
- 启用：`ai.enabled=true` + `ai.h5.enabled=true` + `ai.config`（`is_del=0`）

**写操作拒答**（`UNSUPPORTED`，A10 验证「取消订单」被拒）。匿名/跨用户/写操作三类越权探针 **0 泄漏**。

## 踩坑（已修复 / 已规避）

1. **`sys_configure` 的 `ai.*` 开关 `is_del` 须为 `0`**：`is_del=1` 会让配置对 `is_del=0` 的读取不可见，
   `ai.h5.enabled` 恒关闭（2.2 DDL 种子已修正为 `is_del=0`）。
2. **H5 工具身份参数是 `userId`（非 `phone`）**：`AiToolExecutor.executeH5` 把绑定身份注入 `userId`
   （`IDENTITY_PARAMS={userId}`），且 `resolveExternalId` 返回 `phone:<手机号>` / `anon:<id>` 前缀形式。
   magic-api 端点须**剥 `phone:` 前缀**再查库；`anon:` 前缀（匿名）直接返回空。
3. **magic-api 内部 `execute` 无 `req` 对象**：`MagicAPIService.execute(method,path,context)` 走
   `requestEntity=null` 分支，脚本里 `req` 为 `null`、`#{}`/`?{}` 绑定不到注入参数；
   注入参数经 `putMapIntoContext` 进入**脚本上下文**，须直接取脚本变量（`var phone = userId`）。
4. **工具 `params_schema` 不要 `required:["phone"]`**：绑定访客的手机号是身份（`userId`），非模型抽取项；
   若 `required` 会触发 `NEED_CLARIFY`（模型向用户要手机号）。置空 `{"type":"object","properties":{}}`。
5. **pymysql 2.2.8 缺陷**：同一进程内第 2 条语句执行报 `Data too long`（1406，实为语句编码异常）。
   种子改用 `seed_line.py` **逐行、每行独立进程**执行规避；生产用 `mysql < seed.sql` 无此限制。
6. **H5 页面走 hash 路由**（`/#/h5/chat`）：SPA fallback（`SpaFallbackController`）仅匹配单段路径
   `/{path:[^.]*}`，多段**路径**路由（`/h5/chat`）直接加载会 404（2.1 既有行为，非 2.2 回归）。
   组件/直链均用 **hash 形式**（`/#/h5/chat?channel=<id>`）即可正常加载；多段路径路由的 fallback
   留 2.3 完善。
