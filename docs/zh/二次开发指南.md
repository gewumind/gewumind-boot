## 1 · 先搞清楚：这个仓库是什么

**这是最容易误解的地方，务必先读完。**

`gewumind-boot` 是一个**应用壳工程**，不是完整的产品源码仓库：

```
gewumind-boot （本仓库，git）        ← 你 clone 到的就是这个
├── src/main/java/        仅 3 个 Java 文件（启动类 + 2 个适配）
├── src/main/resources/
│   ├── *.yml             配置文件
│   └── static/           前端【已构建产物】，非源码
├── data/magic-api/       低代码容器：接口 / 组件 / 任务 / 流程（.ms 文件）
├── db/init/              基线建库 SQL
└── libs/                 内核 jar：gewumind-boot-0.3.2.jar

内核（com.gewumind.boot.*）
├── 是什么：magic-api 低代码容器 + sa-token 鉴权 + SSO + 前端 SPA 承载 + 权限体系
├── 在哪：  作为 jar 依赖放在 libs/，由 pom.xml 引用
└── 注意：  【源码不在本仓库】，改内核不在二次开发范围内
```

**本仓库里只有 3 个 Java 文件**，真正的业务能力（菜单、用户、角色、字典、配置中心、
报表、工作流、开放接口……）都在内核 jar 里，以 `.ms` 低代码脚本和已编译的前端产物形式存在。

### 1.1 怎么开始开发？先选一条路

**大多数用户不需要碰源码。** 按你的目标选：

```
                    你要做的事
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
   改平台内核      只做业务功能       让 AI 帮你写
   或加 Java 类
        │               │               │
        ▼               ▼               ▼
   ① 导入 IDEA     ② 下 release     ③ 用 gewumind-skill
      跑源码工程     直接运行+在线开发     Agent 四阶段管线
```

---

#### 路径 ① 导入 IDEA（改内核 / 加 Java 类）

**什么时候选这条**：你要改平台自身的能力（新增 Java 接口、换鉴权、调启动逻辑），
或者需要断点调试 Java 代码。

```bash
git clone <repo-url> gewumind-boot
cd gewumind-boot

# 用 IDEA 打开：File → Open → 选gewumind-boot/pom.xml
# IDEA 会识别为 Maven 工程，自动下载依赖
```

**IDEA 里要做两件事**：

| 配置 | 路径 | 说明 |
|---|---|---|
| JDK | File → Project Structure → Project | **JDK 17+** |
| Lombok | Settings → Plugins | 装 Lombok 插件并勾选 Enable annotation processing |
| 启动 | Run → Edit Configurations | 主类 `com.gewumind.app.GewuMindBootApp` |

**数据库配置**（不要写进 `application.yml`，用环境变量）：

```
Run/Debug Configurations → Environment variables:
   SPRING_DATASOURCE_PASSWORD=你的密码
```

**运行**：

```bash
# 在 IDEA 里直接点 Run，或命令行：
bash scripts/start.sh --dev      # dev 模式：classpath 优先，改 Java 重启即生效
```

> ⚠️ 注意：**前端源码不在本仓库**。改 Java 后端可以直接在 IDEA 里跑；
> 要改界面仍需另外取得前端工程，见 [6 · 前端怎么改](#6--前端怎么改)。

---

#### 路径 ② 下 release 版本直接运行 + 在线开发（推荐给业务开发）

**什么时候选这条**：你只是要做**业务功能**——写接口、写页面、加报表、加审批流。
**不需要 IDE、不需要 Java、不需要构建**。

```
1. 下载发行包    gewumind-boot-app-<版本>.tar.gz（Linux/macOS）或 .zip（Windows）
2. 解压
3. 改 config/application-dev.yml    填数据库地址与密码
4. bash start.bat / start.sh        首次启动自动建库
5. 浏览器打开 http://<服务器IP>:9089   默认 admin / 123456
```

启动后**所有开发都在浏览器里完成**，不用碰任何本地环境：

| 要做什么 | 在哪做 | 要点 |
|---|---|---|
| 写后端接口 | 在线编程 → 接口 | 纯脚本，`Ctrl+Q` 直接运行调试 |
| 写前端页面 | 在线编程 → 组件 | Vue 组件，保存后刷新页面即生效 |
| 加菜单 / 角色 / 字典 | 后台对应菜单 | 可视化配置 |
| 做报表 | 在线编程 → 报表 | 描述式配置 |
| 配审批流 | 在线编程 → 流程 | 定义节点与条件分支 |
| 调通用能力 | 在线编程 → 服务 / 订阅 | SSE / WebSocket / TCP / Redis 等 |

改完想回滚？这些都存在 `data/magic-api/` 下，**直接用备份覆盖回来**即可。

> 💡 **这条路径覆盖了 90% 的需求**，而且有完整的在线调试能力——
> 包括本项目独有的「监听调试」（用真实前端请求打断点）。

---

#### 路径 ③ 用 gewumind-skill（让 AI 帮你开发）

**什么时候选这条**：你希望 AI Agent 按规范自动产出成套的建表 SQL、接口脚本、
页面组件与菜单，并且能一键发布到运行中的系统。

**前置**：已按路径 ② 跑起来一个可用实例（skill 要连到这个实例上发布）。

```
技能仓库：https://github.com/gewumind/gewumind-skill
```

它是一条**四阶段管线**：

```
需求文档  →  UI/数据库/API 设计文档  →  生成代码  →  发布到后端
（阶段1）      （阶段2）                 （阶段3）      （阶段4）
```

产物包含：建表 SQL、magic-api 脚本、Vue 组件、菜单与字典 SQL、预置数据。

接入方式二选一：

| 方式 | 说明 |
|---|---|
| **MCP**（推荐） | 后端自带 `/mcp` 端点，配置一次即可用 |
| **REST** | `POST /api/ai/bundle/apply` + `X-AI-Key` 头 |

详见 [AI 开发](./AI开发.md)。

---

#### 三条路径怎么选

| 你的情况 | 选 |
|---|---|
| 只想做业务功能（接口、页面、报表、流程） | **②** 最省事 |
| 想让 AI 按规范批量产出模块 | **③** |
| 要改平台内核、加 Java 类、调启动逻辑 | **①** |
| 先跑起来看看效果 | **②** → 之后按需升级到 ① 或 ③ |

> 💡 **建议顺序**：先走 ② 跑通、熟悉系统；确有需要再 ①。
> ③ 可以随时叠加在任何一条之上。

## 3 · 三个 Java 文件（别删）

### 3.1 `GewuMindBootApp.java` —— 启动类

```java
@SpringBootApplication(scanBasePackages = {"com.gewumind.app", "com.gewumind"})
```

`scanBasePackages` **必须同时包含两个包**：

- `com.gewumind.app` —— 本工程的类
- `com.gewumind` —— 内核包（magic-api 容器、登录鉴权、前端路由 fallback）

少扫一个，magic-api 脚本、登录鉴权、前端 SPA 路由都会失效。

### 3.2 `ApiPrefixConfiguration.java` —— 剥掉 `/api` 前缀

前端的请求拦截器会给**所有**业务请求加 `/api` 前缀：

```js
if (config.url && !config.url.startsWith('/api') && !config.url.startsWith('http')) {
    config.url = '/api' + config.url
}
```

生产构建没有开发代理，所以这个前缀必须由后端**剥掉**：

```
/api/system/security/login      →  /system/security/login
/api/ai/system-config           →  /ai/system-config
```

前缀值可配：`gewumind.api-prefix`（默认 `/api`）。**如果你把前端请求封装改成不加前缀，这里可以改成空字符串，但两处必须一致。**

### 3.3 `SsoClientEntryController.java` —— SSO 端点

提供 `GET /sso/login` 与 `GET /sso/logout`。

内核修掉 SSO 重复映射（删掉了空壳 Controller）时，连带丢了这两个端点，所以在本工程补回来。**不要删。**

## 4 · 二次开发该改哪里

### 4.1 加自己的 Java 代码

新建类，放到 `com.gewumind.app` 包下即可被扫描：

```
src/main/java/com/gewumind/app/myfeature/MyController.java
```

```java
package com.gewumind.app.myfeature;

import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/myfeature")
public class MyController {

    @GetMapping("/hello")
    public Object hello() {
        return java.util.Map.of("ok", true);
    }
}
```

访问 `http://<host>:9089/myfeature/hello`。

> ⚠️ **路由不要用 `/system` 开头的路径**——已被内核占用，会冲突。
> 推荐加一个自己的前缀（如 `/api-ext`、`/biz`），或直接用 `.ms` 写接口。

### 4.2 业务功能优先用 `.ms`

绝大多数需求**不需要写 Java**。加一个增删改查模块的完整流程见《低代码开发教程》。

判断标准：

| 需求 | 首选 |
|---|---|
| 对外提供 JSON 接口 | `.ms` 接口 |
| 后台管理页面 | `.ms` 组件 + 菜单 |
| 定时任务 | `.ms` 定时任务 |
| 报表 | `data/magic-api/report/` |
| 审批流 | `.ms` 流程 |
| 需要 Java 特有能力（文件流、AOP、连接池直连…） | 写 Java |

### 4.3 加配置项

见《使用手册》第 8 章「配置中心逐项详解」。运行期参数在后台改，无需重启。

## 5 · 构建与运行

### 5.1 环境要求

JDK 17+、MySQL 5.7+/8.0+。**不需要** Node.js / Maven 之外的东西（发版时才需要 Maven）。

### 5.2 常用命令

```bash
# 启动（首次会自动建库）
SPRING_DATASOURCE_PASSWORD='你的密码' bash scripts/start.sh

# 停止
bash scripts/stop.sh

# 重新打包
bash scripts/stop.sh
mvn -q -o package -DskipTests
bash scripts/start.sh

# 开发模式（classpath 优先，改 Java 重启即生效）
bash scripts/start.sh --dev
```

> ⚠️ **铁律：绝不在实例运行时原地覆盖 fat jar。**
> Spring Boot 的 fat jar 是「嵌套 jar + 随机访问」结构，JVM 运行时按需从中读 class。
> **服务运行期间执行 `mvn package`，运行中的实例会随机抛 `NoClassDefFoundError`、接口返回 404。**
> 顺序恒为 **stop → package → start**。`build-dist.sh` 已内置该检查。

### 5.3 日志

`logs/gewumind-boot-app.log`。定位启动问题先看这里。

## 6 · 前端怎么改

### 6.1 现状

`src/main/resources/static/` 是**已构建产物**，随仓库提交，保证 clone 就能打开后台。

**前端源码不在本仓库**，它在一个独立的前端工程里（Vue 3 + Vite），不在版本控制范围内。

### 6.2 改业务页面（推荐，不需要前端源码）

用 `.ms` 动态组件。后台「在线编程 → 组件」标签可直接编辑，保存后**刷新页面**即生效。详见《低代码开发教程》第 7 章。

### 6.3 改整体界面（需要前端源码工程）

拿到前端源码后，构建并同步：

```bash
cd /path/to/frontend

# 1) 构建
VITE_APP_BASE_API='' npm run build        # → dist/

# 2) 全量同步到本仓库（先删后拷，避免残留旧 hash 文件）
cd /path/to/gewumind-boot
bash scripts/stop.sh
rm -rf src/main/resources/static
cp -r /path/to/frontend/dist src/main/resources/static

# 3) 重打包启动
mvn -q -o package -DskipTests
bash scripts/start.sh
```

**三个必须遵守的约束：**

1. **`VITE_APP_BASE_API=''` 不能省。** 前端 `.env.production` 里写死了内网地址（如 `http://192.168.x.x:8089/`），而本应用是同源部署，必须在构建时用环境变量覆盖（shell 环境变量优先级高于 `.env`）。CI 也会扫描产物里的内网 IP 与本机路径，带进去直接构建失败。

2. **同步必须「先删后拷」。** 直接 `cp -r` 会把上一次的旧 hash chunk 留在仓库里，仓库体积持续膨胀。

3. **别动混淆配置。** 构建插件里有自定义的 `obfuscateSkipPreloadChunks`，它会跳过含 preload 胶水的 chunk。破坏它会导致运行时 `TypeError: deps.map is not a function`，页面全白、路由只注册一半。改完务必在浏览器里验证页面能渲染。

确认跑的是哪一版：

```bash
grep -o 'index-[a-z0-9]*\.js' src/main/resources/static/index.html   # 仓库里的
curl -s http://localhost:9089/ | grep -o 'index-[a-z0-9]*\.js'          # 实际服务的
```

## 7 · 低代码文件编程

`.ms` 文件是「JSON 头 + 分隔符 + 源码」：

```
{ "id":"...", "path":"/list", "method":"POST", ... }
================================
<源码正文>
```

### ⚠️ 分隔符必须带首尾 `\r\n`

后端 `ComponentManagementController.SEPARATOR` 定义为 `"\r\n" + 32个"=" + "\r\n"`。
一旦不匹配（最常见是漏掉 `\r\n`），后端会把**整个文件（含 JSON 头）当成源码**，
在线编辑器里表现为「内容是空的」或一大坨 JSON。

Node 参考实现：

```js
const SEP = '\r\n================================\r\n'
const i = content.indexOf(SEP)
if (i < 0) throw new Error(`${file}: 分隔符不匹配（缺少首尾 \\r\\n）`)
const header = JSON.parse(content.slice(0, i))
const source = content.slice(i + SEP.length)
// 写回：JSON.stringify(header, null, 2) + SEP + source
```

**通过后台编辑器保存是安全的**（后端自己写回）；只有用脚本批量改 `.ms` 时才必须自己保证。

改完源码还要同步更新 JSON 头里的 `compileJs` / `compileCss`（运行时直接 eval 它们），否则页面不变。

## 9 · 打包发行版

```bash
bash scripts/stop.sh                 # 必须先停，否则脚本拒绝执行
bash scripts/build-dist.sh           # → dist/gewumind-boot-app-<版本>.tar.gz + .zip

# Windows
scripts\stop.bat
scripts\build-dist.bat
```

两个平台行为一致：都先解析 pom 版本、跑 `mvn package`、组装目录、打出 `.tar.gz` 与 `.zip`。
Windows 版用系统自带 `tar.exe`（需 Win10 1803+）打 `.tar.gz`，zip 走 PowerShell `Compress-Archive`。

> `build-dist.*` **不会打进发行包**——它需要 Maven 与源码树，对发行包用户没有意义。

包名跟**应用**走（`gewumind-boot-app` + pom 的 `<version>`），不跟内核走——内核版本只是依赖。

产物布局：

```
gewumind-boot-app-<版本>/
├── bin/     start/stop + gen-ssl-cert（.sh 与 .bat 双份）
├── libs/    gewumind-boot-app.jar
├── config/  application.yml + 各 profile
├── data/    magic-api（接口与组件，备份重点）
├── db/      基线 SQL
├── docs/    全部文档与截图
├── logs/ upload/ reports/
├── DEPLOY.md
└── LICENSE / NOTICE / README
```

启动脚本自动识别「发行包布局（jar 在 `libs/`、配置在 `config/`）」与「源码布局（jar 在 `target/`）」。

## 10 · 提交前检查

CI（`mvn -B clean package`）会自检 jar 内含前端产物，并扫描内网 IP、密钥与本机绝对路径。提交前自查：

- [ ] `src/main/resources/static/` 里没有 `192.168.x.x`
- [ ] 没有本机绝对路径（`/data/...`）
- [ ] `*.yml`、`.env` 里没有真实密码
- [ ] 没提交 `logs/` `upload/` `reports/` `dist/` `target/`（已在 `.gitignore`）
- [ ] 没提交 `certs/` `*.p12`
- [ ] 新增脚本已 `chmod +x`
