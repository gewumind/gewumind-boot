## 整体结构

```
浏览器 ──► gewumind-boot-app.jar（端口 9089）
              │
              ├─ 内核 jar（libs/ 里那个 com.gewumind.boot.*）
              │    magic-api 容器 · sa-token 会话 · SSO · 动态组件加载 · 授权门禁
              │
              ├─ 本工程（src/main/java/com/gewumind/app/，仅 3 个类）
              │    启动类 · /api 前缀剥离 · SSO 入口补全
              │
              ├─ data/zh/magic-api/     ← 业务接口和页面组件写在这里
              └─ MySQL               ← 结构与基础数据由 db/init/01-baseline.sql 定义
```

## 模块职责

| 模块 | 位置 | 你会在什么时候动它 |
|------|------|-------------------|
| **内核 jar** | `libs/com/gewumind/gewumind-boot/` | 基本不动。要改内核能力（工作流、报表、授权逻辑…）请去内核仓库 |
| **本工程代码** | `src/main/java/com/gewumind/app/` | 只在需要改启动行为或拦截器时才动，一共 3 个类 |
| **接口脚本** | `data/zh/magic-api/api/` | **写后端接口**。每个 `.ms` 文件是一个接口，路径 `/分组/名称.ms` |
| **页面组件** | `data/zh/magic-api/component/` | **写前端页面**。每个 `.ms` 是一个 Vue 单文件组件，按分组目录组织 |
| **定时任务** | `data/zh/magic-api/task/` | 写定时任务 |
| **工作流定义** | `data/zh/magic-api/workflow/` | 写工作流流程 |
| **前端产物** | `src/main/resources/static/` | 通常不动。只在更换前端版本时整体替换 |
| **数据库基线** | `db/init/01-baseline.sql` | 新环境导入用。**已有环境不要重复导入** |
| **配置** | `src/main/resources/application-*.yml` | 部署参数；运行期可调项在后台「配置中心」 |

> `data/zh/magic-api/` 里的 `.ms` 文件是**接口与页面的真正来源**：后端启动时读取它们，
> 后台的在线编辑器保存时也是写回这些文件。改完文件、刷新页面就生效，不用重新打包。

## 请求怎么流转

**调用一个接口**

```
浏览器 → /api/system/security/login
       → ApiPrefixConfiguration 剥掉 /api 前缀
       → magic-api 匹配 data/zh/magic-api/api/系统管理/安全/登录.ms
       → 脚本执行 SQL（连 MySQL）
       → 返回 JSON
```

**加载一个页面**

```
浏览器 → /
       → static/index.html（SPA）
       → 前端请求 /system/component/runtime/list
       → 后端扫 data/zh/magic-api/component/**/*.ms
       → 返回每个组件的 compileJs，前端注册为全局组件并渲染
```

**发布一个 AI 生成的模块**

```
AI Agent → MCP /mcp（带 X-AI-Key）
         → bundle_apply 工具
         → 写 db 里的表 + data/zh/magic-api/ 下的 .ms 文件
         → 自动备份，刷新页面即可见
```

## 我要改 X，该动哪里

| 我想… | 改哪里 |
|-------|--------|
| 加一个后端接口 | 在后台「在线编程」里新建，或直接在 `data/zh/magic-api/api/` 下加 `.ms` |
| 改某个接口的逻辑 | 找到对应的 `.ms`，编辑脚本部分 |
| 加一个页面 | 后台新建页面（会生成 `.ms` 到 `data/zh/magic-api/component/`） |
| 加菜单 / 角色 / 字典 | 后台对应管理页，数据在 `sys_menu` / `sys_role` / `sys_dict` |
| 改数据库连接、端口 | `src/main/resources/application-<profile>.yml`，或用环境变量覆盖 |
| 改运行期开关（AI、Kafka、Redis…） | 后台「配置中心」，落库到 `sys_configure` |
| 换前端版本 | 整体替换 `src/main/resources/static/` 后重新打包 |

## 环境（profile）

| profile | 用途 | 数据源 | AI Key |
|---------|------|--------|--------|
| `dev`（默认） | 本地开发 | 本机 MySQL，有默认值 | 自动签发 + 允许自助签发 |
| `demo` | 演示 / 试用 | 本机 MySQL，有默认值 | 自动签发 + 允许自助签发 |
| `online` | **生产** | **必须用环境变量提供** | 不签发 + **禁止自助签发** |
| `docker` | 容器 | 指向 compose 里的 `db` | 不签发 + 禁止自助签发 |

```bash
java -jar target/gewumind-boot-app.jar --spring.profiles.active=online
# 或 SPRING_PROFILES_ACTIVE=online
```

## 端点速查

```
GET  /                        后台首页（SPA）
GET  /magic/web               接口文档 / 在线编程
GET  /system/security/login   登录（magic-api 脚本，返回 token）
POST /api/system/security/login   同上，带 /api 前缀，入口统一剥掉
GET  /druid                   Druid 监控（仅 dev / demo 开启）

GET  /mcp                     MCP SSE 端点            ┐ 需要 X-AI-Key
POST /ai/bundle/apply         AI 发布模块              ┘
GET  /system/license/status   授权状态
GET  /system/ai-keys/list     AI Key 管理（需后台登录 token）
GET  /system/component/runtime/list   页面组件清单
```

## 常见问题

**端口被占用 / 启动脚本报「端口已被占用」**
脚本会提前检查并直接报错。查占用：`ss -ltnp | grep 9089`；换端口：`SERVER_PORT=9090 bash scripts/start.sh`。

**打开后台是 404**
说明 jar 里没有前端产物。确认 `src/main/resources/static/index.html` 存在后重新 `mvn clean package`。

**登录提示用户名或密码错误**
默认账号 `admin` / `123456`（前端提交的是 SHA-256 哈希，不是明文）。用 curl 手工验证时要把密码做 SHA-256 再传。

**AI 相关接口返回 401 / INVALID_KEY**
MCP 与 `/ai/**` 需要 `X-AI-Key: <keyId>:<secret>`。dev 模式下首次启动会自动生成并打印在启动日志里：`grep "X-AI-Key" logs/gewumind-boot-app.log`。也可以在后台自助签发（见 README 的「AI / MCP 接入」章节）。

**数据库连不上**
仓库里不写死密码，必须注入 `SPRING_DATASOURCE_PASSWORD`。`online` profile 下 URL 与账号也没有默认值，缺任一项会直接启动失败 —— 这是有意的，避免静默连错库。

**改了 `.ms` 但页面没变**
改动在 `data/zh/magic-api/` 下的组件文件；先确认文件确实保存，再刷新页面（必要时强制刷新清缓存）。若改动涉及 Java 代码，需要重启。

**前端白屏、等一个连不上的主机**
前端产物里若写死了后端地址就会这样。本工程要求同源相对路径（`VITE_APP_BASE_API` 留空），后端和前端同端口提供服务。
