## 1. 环境要求

| 项目 | 要求 | 说明 |
|---|---|---|
| JDK | **17 或以上** | Spring Boot 3.2 基准。低版本直接启动失败 |
| MySQL | 5.7+ / 8.0+ | 需 `utf8mb4` 字符集 |
| 内存 | 建议 ≥ 2GB | 默认 `-Xms512m -Xmx2g`，按并发调整 |
| 端口 | 默认 `9089` | 可改，启动前须未被占用 |
| 磁盘 | ≥ 2GB | 含 jar(112MB)、日志、上传文件、报表 |

> **不需要** Node.js、npm、Maven、Git —— 发行包是已构建好的 fat jar。只有从源码构建才需要（见《二次开发指南》）。

## 2. 快速开始

### 2.1 获取发行包

| 平台 | 文件 |
|---|---|
| Linux / macOS | `gewumind-boot-app-1.1.0.tar.gz` |
| Windows | `gewumind-boot-app-1.1.0.zip` |

两者内容完全一致，只是归档格式不同。

### 2.2 解压

```bash
# Linux / macOS
tar -xzf gewumind-boot-app-1.1.0.tar.gz

# Windows：直接右键解压 zip
```

### 2.3 配置数据库

编辑 `config/application-dev.yml`：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/gewumind-boot?zeroDateTimeBehavior=convertToNull&useUnicode=true&characterEncoding=UTF8&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai
    username: root
    password: 你的密码
```

> 也**不建议**把密码写进文件，用环境变量覆盖（见 [4.3 密码管理](#43-密码管理不要把密码写进文件)）。

### 2.4 初始化数据库

发行包内已含基线脚本 `db/init/01-baseline.sql`。二选一：

**方式 A · 让应用自动建表（推荐首次使用）**

`start.sh` 首次启动会自动执行基线 SQL 建表并写入初始数据，无需手工操作。

**方式 B · 手工导入**

```bash
mysql -uroot -p gewumind-boot < db/init/01-baseline.sql
```

> 两种方式**不要同时做**。若已手工导入，启动日志会出现"表已存在"的提示，属正常。

> ⚠️ `01-baseline.sql` 只含**平台表**（系统表 / 菜单 / 字典 / 组织机构等），**不含业务表**
> （`t_*`）。业务项目请自带 `db/init/02-<业务>.sql`，按 `01` → `02` 顺序导入，
> 否则业务接口在新环境会全部报错。

### 2.5 启动

```bash
bash start.sh            # Linux / macOS
start.bat                # Windows（双击也可）
```

看到以下输出即成功：

```
✓ 启动成功 / started  http://localhost:9089
  后台管理  http://localhost:9089/        （默认 admin / 123456）
  接口文档  http://localhost:9089/magic/web
  Druid     http://localhost:9089/druid   （admin / 123456）
```

日志：`logs/gewumind-boot-app.log`

### 2.6 访问

浏览器打开 `http://<服务器IP>:9089`

![登录页](../screenshots/00-登录页.png)

默认账号 **`admin` / `123456`** —— **首次登录后请立即在「用户管理」中修改密码。**

### 2.7 停止

```bash
bash stop.sh             # Linux / macOS
stop.bat                 # Windows
```

## 3. 数据库准备

### 3.1 建库

```sql
CREATE DATABASE gewumind-boot DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

**必须 `utf8mb4`**，否则存 emoji、中文外的特殊字符、以及上传文件名会乱码或报错。

### 3.2 数据库版本兼容

- **MySQL 8.0**：需带 `allowPublicKeyRetrieval=true`（配置里已带），否则报 `Public Key Retrieval is not allowed`。
- **MySQL 5.7**：JDBC 驱动 8.x 连 5.7 正常，但请确认 `sql_mode` 不含 `ONLY_FULL_GROUP_BY` 导致的兼容问题（本项目查询已规避）。

### 3.3 连接池

默认 HikariCP，连接信息见 `application.yml` 的 `spring.datasource.hikari`。生产环境建议：

```yaml
maximum-pool-size: 20        # 与数据库 max_connections 匹配
minimum-idle: 5
connection-timeout: 30000
```

## 3.5 国际化（语言）

**数据库（部署级，二选一）**
- 中文：`01-baseline.sql` + `db/init/zh/02-seed.sql` + `db/init/zh/03-demo.sql`
- 英文：`01-baseline.sql` + `db/init/en/02-seed.sql` + `db/init/en/03-demo.sql`
- 已有中文库切英文：`db/init/en/upgrade-from-zh.sql`

**前端**
- 访问 `?lang=en`，或控制台 `localStorage.gw_lang='en'` 后刷新
- 语言包：`data/i18n/<lang>.json`（`en.json` 为示例）；复制后翻译 value
- 内核消息覆盖：`data/i18n/messages_<lang>.properties`
- 语言接口：`POST /api/i18n/pack {"lang":"en"}` → 读取 `data/i18n/en.json`

**限制**
- DOM 级翻译，业务数据不翻译；动态拼接用 `patterns`


**magic-api 资源英文名**

```bash
python3 scripts/i18n-magic-api.py      # 生成 data/magic-api-en
```

- 只翻译显示名（`group.json.name`、`.ms` header `name`）；ID / 路径 / URL / 脚本不变
- 英文部署：用 `data/magic-api-en` 替换 `data/magic-api`（或把 magic-api 资源目录指向它）
- 组件页面文案仍由 `data/i18n/<lang>.json` 运行时翻译

## 4. 配置说明

### 4.1 profile（运行环境）

| profile | 用途 | 说明 |
|---|---|---|
| `dev` | 开发/内网 | 宽松日志、详细 SQL |
| `online` | **生产（默认推荐）** | 精简日志、错误页不泄露栈 |
| `docker` | 容器 | 路径与主机名适配 |
| `demo` | 演示 | 内置演示数据 |

```bash
bash start.sh --profile online
```

### 4.2 常用启动参数

```bash
# 换端口
SERVER_PORT=8080 bash start.sh

# 调 JVM 内存
JVM_OPTS="-Xms1g -Xmx4g" bash start.sh

# 组合
SERVER_PORT=8080 JVM_OPTS="-Xms1g -Xmx4g" bash start.sh --profile online
```

### 4.3 密码管理：不要把密码写进文件

所有敏感项都支持环境变量覆盖：

```bash
SPRING_DATASOURCE_PASSWORD='真实密码' bash start.sh
```

| 环境变量 | 对应配置 |
|---|---|
| `SPRING_DATASOURCE_URL` | `spring.datasource.url` |
| `SPRING_DATASOURCE_USERNAME` | `spring.datasource.username` |
| `SPRING_DATASOURCE_PASSWORD` | `spring.datasource.password` |

生产环境建议写进 systemd unit / Docker 的 env 文件，不要进版本库。

### 4.4 配置中心的运行期配置

端口、数据库连接这类**启动期**参数在 `config/*.yml`；
系统名称、Logo、主题、验证码、水印这类**运行期**参数在「配置中心」页面改，无需重启。详见《使用手册》。

## 5. 多平台部署

### 5.1 Linux（systemd，推荐生产）

`/etc/systemd/system/gewumind-boot.service`：

```ini
[Unit]
Description=GewuMind Boot
After=network.target mysql.service

[Service]
Type=simple
User=gewumind
WorkingDirectory=/opt/gewumind-boot
Environment="SERVER_PORT=9089"
Environment="JVM_OPTS=-Xms1g -Xmx4g"
EnvironmentFile=/opt/gewumind-boot/.env     # 放 SPRING_DATASOURCE_PASSWORD 等
ExecStart=/bin/bash start.sh
ExecStop=/bin/bash stop.sh
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now gewumind-boot
sudo journalctl -u gewumind-boot -f
```

### 5.2 Linux（裸机 / Docker 主机）

直接 `./start.sh`，用 `nohup` 自行托管即可；或用 `screen`/`tmux` 保持会话。

### 5.3 macOS

与 Linux 相同（`.sh` 脚本通用）。注意 macOS 自带的是较旧的 bash 3.2，脚本已兼容。

### 5.4 Windows

```bat
start.bat
stop.bat
```

或 PowerShell：

```powershell
$env:SERVER_PORT="9089"
$env:SPRING_DATASOURCE_PASSWORD="真实密码"
.\start.bat
```

> **注意事项**
> - 需把 JDK 的 `bin` 加入 `PATH`，否则报 `'java' 不是内部或外部命令`。
> - 控制台窗口关掉进程就停；要常驻请用 [NSSM](https://nssm.cc/) 注册为服务。
> - `.bat` 不支持 `SERVER_PORT=9080 bash start.sh` 这种前缀写法，需用 `set` 或 PowerShell 设环境变量。

### 5.5 Docker

发行包不含 `Dockerfile`，用如下最小配置即可（构建上下文指向解压后的目录）：

```dockerfile
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY libs/gewumind-boot-app.jar app.jar
COPY config/ config/
COPY data/ data/
COPY db/ db/
EXPOSE 9089
ENV SERVER_PORT=9089 \
    JAVA_OPTS="-Xms512m -Xmx2g"
ENTRYPOINT ["sh","-c","exec java $JAVA_OPTS -Dserver.port=$SERVER_PORT -jar app.jar --spring.config.additional-location=file:./config/ --spring.profiles.active=docker"]
```

```bash
docker build -t gewumind-boot:1.1.0 .
docker run -d --name gewumind -p 9089:9089 \
  -e SPRING_DATASOURCE_PASSWORD='真实密码' \
  -v gewumind-data:/app/data \
  -v gewumind-upload:/app/upload \
  gewumind-boot:1.1.0
```

> ⚠️ **`data/` 必须挂持久卷**。`data/magic-api` 里是你所有的接口与组件，容器删了就全没了。

## 6. HTTPS 与证书

### 6.1 生成自签证书（内网够用）

```bash
bash bin/gen-ssl-cert.sh          # Windows: bin\gen-ssl-cert.bat
```

脚本会生成 `certs/` 目录与 keystore，并提示你把参数填进 `config/application.yml`。

### 6.2 启用

`config/application.yml`：

```yaml
server:
  ssl:
    enabled: true
    key-store: file:./certs/gewumind.p12
    key-store-password: 你的密码
    key-store-type: PKCS12
```

> **必须用 `file:./certs/...` 的绝对/相对文件路径**，不能用 `classpath:`——证书不入 jar。

### 6.3 正式证书

把 Nginx/Caddy 终止 TLS，再反代到后端：

```nginx
server {
    listen 443 ssl;
    server_name your.domain.com;
    ssl_certificate     /etc/nginx/cert/fullchain.pem;
    ssl_certificate_key /etc/nginx/cert/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:9089;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

启用 HTTPS 后前端 WebSocket 会自动走 `wss://`，无需额外配置。

## 7. 生产部署检查清单

上线前逐条确认：

- [ ] 已改掉 `admin` 的默认密码 `123456`
- [ ] 已删除或改名默认低权限账号
- [ ] 数据库密码通过环境变量注入，未写进配置文件
- [ ] `config/*.yml` 与 `.env` 未提交到版本库
- [ ] 使用 `--profile online` 启动
- [ ] 已配置 JVM 堆大小（`-Xms` = `-Xmx`，避免抖动）
- [ ] 日志目录 `logs/` 有轮转策略（否则会涨满磁盘）
- [ ] `data/`、`upload/`、`db/` 已纳入备份
- [ ] 已配置 HTTPS 或确认在内网可信环境
- [ ] 防火墙已放行 9089（或只对内网开放）
- [ ] `/druid` 监控页已限制访问（默认 `admin/123456`，同样要改）
- [ ] 已实测一次重启，验证 `stop.sh` / `start.sh` 与开机自启

## 8. 升级

```bash
bash stop.sh                              # 1. 先停（重要，见下方警告）
cp -r data data-backup-$(date +%F)         # 2. 备份低代码容器
mysqldump -uroot -p gewumind-boot > db-backup-$(date +%F).sql   # 3. 备份数据库

tar -xzf gewumind-boot-0.4.0.tar.gz        # 4. 解压新版
#    编辑 config/application.yml（保留原有配置，尤其是数据源与密码）

bash start.sh --profile online            # 5. 启动
```

> ⚠️ **升级前必须先 `stop.sh`。**
> Spring Boot 的 fat jar 是"嵌套 jar + 随机访问"结构，JVM 运行时按需从 jar 文件里读 class。
> **服务运行期间执行 `mvn package` 或直接覆盖这个 jar，运行中的实例会随机抛
> `NoClassDefFoundError` / `ClassNotFoundException`，接口返回 404。** 这不是新版本的 bug，
> 而是在线覆盖 jar 的必然结果。正确顺序恒为 **stop → 替换 → start**。

### 8.1 数据库升级

新版若有基线变更，新脚本在 `db/` 目录里（如 `02-xxx.sql`），手工执行即可。
基线脚本是**幂等**的（`CREATE TABLE IF NOT EXISTS` / `INSERT ... ON DUPLICATE`），重复执行安全。

**业务基线与平台基线分离维护**：`01-baseline.sql` 属平台资产，升级时整体替换；
业务项目的表结构与初始数据放 `db/init/02-<业务>.sql`，由项目自己版本管理。
这样升级平台内核不会覆盖掉业务数据。

## 9. 备份与恢复

### 9.1 需要备份什么

| 内容 | 位置 | 重要性 |
|---|---|---|
| 数据库 | MySQL | ★★★ 全部业务数据、用户、菜单、配置 |
| 低代码容器 | `data/magic-api/` | ★★★ 所有接口、组件、任务、流程 |
| 上传文件 | `upload/` | ★★ Logo、附件、图片 |
| 报表输出 | `reports/` | ★ 生成的报表文件 |
| 配置 | `config/` | ★★ 数据源、端口、HTTPS |

> `logs/` 不需要备份。

### 9.2 一键备份示例

```bash
#!/bin/bash
# backup.sh
set -e
TS=$(date +%Y%m%d-%H%M%S)
DEST="/backup/gewumind-$TS"
mkdir -p "$DEST"

mysqldump -uroot -p"$MYSQL_PWD" gewumind-boot > "$DEST/db.sql"
tar -czf "$DEST-data.tar.gz" data upload config
echo "备份完成: $DEST"
```

配 crontab：

```cron
0 2 * * * /opt/gewumind-boot/backup.sh
```

### 9.3 恢复

```bash
bash stop.sh
mysql -uroot -p gewumind-boot < db.sql
tar -xzf data.tar.gz
bash start.sh
```

## 10. 常见部署问题

### Q：`'java' 不是内部或外部命令` / `java: command not found`

没装 JDK 或没配 `PATH`。装 JDK 17+ 后把 `$JAVA_HOME/bin` 加入 `PATH`。

### Q：启动报 `Port 9089 was already in use`

端口被占。脚本本身会**明确报错退出**（不会误报启动成功）。换端口或查占用：

```bash
ss -ltnp | grep 9089
SERVER_PORT=9090 bash start.sh
```

### Q：`UnsupportedClassVersionError` / `class file version 61.0`

JDK 版本太低，本项目要 **17+**。

### Q：`Access denied for user` / `Public Key Retrieval is not allowed`

MySQL 8.0 的认证问题。确认 url 里有 `allowPublicKeyRetrieval=true`。

### Q：启动成功但页面 404 / `NoClassDefFoundError`

**几乎都是"运行中覆盖了 jar"**。执行 `stop.sh` 后重新 `start.sh` 即可。见 [8. 升级](#8-升级) 的警告。

### Q：能登录但菜单空白 / 接口 403

- 菜单空白 → 角色没分配菜单权限，或前端静态产物与后端不匹配
- 接口 403 → 当前角色缺该接口的权限码。给角色补权限，或临时用 `admin` 验证

### Q：`data/magic-api` 里的东西丢了

检查容器是否用了持久卷（见 [5.5 Docker](#55-docker)）；或误删了目录。

### Q：怎么确认跑的是哪一版

```bash
curl -s http://localhost:9089/ | grep -o 'index-[a-z0-9]*\.js'   # 实际服务的入口
unzip -l libs/gewumind-boot-app.jar | grep 'static/index.html'     # jar 内是否有前端
```

两者一致即部署正确。浏览器显示旧样式是**缓存**，强刷（Ctrl+F5）。
